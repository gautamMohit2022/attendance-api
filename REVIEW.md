# REVIEW.md

Review of the starter `app/main.py` (helpers and endpoints). Every item below is fixed in the submitted code.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Grace test is `minutes > 10` on a value already floored to whole minutes, so 09:40:01 to 09:40:59 give `minutes == 10` and are never late. R2 says "strictly more than 10:00", so 09:40:01 must give 10. | Shift 09:30, punch-in 09:40:01 returns 0 instead of 10. | Work in whole seconds: late when `seconds > 600`, then `seconds // 60`. |
| 2 | `compute_late_minutes` | Builds the shift start with `punch_in.replace(hour=..)` on the punch-in's own (naive, server-local or UTC) date, not IST. It also ignores overnight shifts. | Server in UTC: IST 09:45 is 04:15 UTC, so it compares 04:15 with 09:30 and gets a negative value (returns 0). Overnight 22:00 shift, punch-in 22:20 gives wrong or zero values. | `attendance_date()` + `shift_bounds()` compute the IST shift start for the attendance date (R1), overnight-aware; subtraction is done on aware datetimes. |
| 3 | `compute_late_minutes` / `punch_in` | Seconds are not truncated before calculating (R1), so 09:40:00.900 can count as late. | Punch-in at `...:00.900` after 09:40:00. | `trunc_sec()` is applied to every instant before any calculation and the truncated value is stored and returned. |
| 4 | `compute_work_hours` | Python `round()` is banker's rounding on a float; R4 wants half-up. | 18 seconds of work = 0.005 h returns 0.0 instead of 0.01. | Integer seconds, `Decimal` and `ROUND_HALF_UP`. |
| 5 | `compute_overtime` | No 30-minute minimum (R3). It also puts the shift end on the record date even for overnight shifts, and subtracts an aware value (`end`) from a naive one (`punch_out`). | 5 minutes past shift end returns 5, not 0. With the (naive) datetime the endpoint would produce, it raises `TypeError` -> 500. Overnight 06:40 punch-out is computed against 06:00 on the wrong day. | Minimum of 30 enforced; `shift_bounds()` puts the end of an overnight shift on the next day; all datetimes are aware UTC. |
| 6 | Whole file, `datetime.now()` / `datetime.fromtimestamp()` | Naive local-time datetimes everywhere (`created_at`, punch-in). The meaning depends on the server's time zone, and PyMongo returns naive datetimes. | Run on a server whose TZ is not UTC: stored instants are off by the offset and dates change near midnight. | Client uses `tz_aware=True`; all instants are aware UTC; conversion to/from epoch milliseconds happens in two helpers at the boundary. |
| 7 | `create_employee` | Check-then-insert (`find_one` then `insert_one`) with no unique index: two parallel creates both pass the check and both insert. | 20 parallel POSTs with the same `emp_code` give several 201s and duplicate documents. | Unique index on `emp_code` created at startup; the insert catches `DuplicateKeyError` and returns 409. |
| 8 | `create_employee` / `EmployeeIn` | No validation: `emp_code` format, email, `HH:MM` shifts, `joined_on` as a real date, `shift_start != shift_end`, length limits. `created_at` is returned as a datetime, not epoch ms. | `{"emp_code":"x","shift_start":"99:99","joined_on":"nope"}` is accepted (201). | Pydantic model with patterns, date validation and a model validator; response converts `created_at` to epoch ms. |
| 9 | `list_employees` | `skip = page * page_size` (page 1 skips the first page), `total` counts the whole collection instead of the filtered set, no sort, `page_size` unbounded, `page=0`/negative accepted. | `?page=1` never returns the first employees; `?department=X` shows the total of all employees; page boundaries shuffle between calls. | `skip = (page-1)*page_size`, `count_documents(filter)`, sort by `emp_code`, `Query(ge=1, le=100)`. |
| 10 | `punch_in` | `emp` is not checked: unknown employee -> `emp[...]` on `None` -> 500 instead of 404. | POST with an unknown `emp_code`. | Explicit 404. |
| 11 | `punch_in` | Check-then-insert race again (`find_one` then `insert_one`). | Parallel identical punch-ins give more than one 201 and duplicate rows. | Unique `(emp_code, date)` index; `DuplicateKeyError` -> 409. |
| 12 | `punch_in` | `if body.punched_at` treats `0` as "missing"; `punched_at: Optional[int]` accepts floats and numeric strings (lax coercion) and values in seconds; `status: str` accepts anything, including `ABSENT`. Date comes from the server-local date, no overnight rule. | `punched_at=1783312500` (seconds), `"1783312500000"`, `status="ABSENT"` all return 201. | Strict `int` with range check (rejects seconds, floats, strings, bool), `status` limited to PRESENT / WFH / ON_DUTY, `is not None` check, date from `attendance_date()` (R1). |
| 13 | `punch_in` (response) | Returns `id` (the ObjectId) and datetimes instead of epoch ms; the contract says `_id` never leaves the API. Derived fields are not computed by one shared function. | Response contains `"id": "65f..."` and an ISO string for `punch_in`. | `attendance_out()` builds the response explicitly (no `_id`, epoch ms). |
| 14 | `list_attendance` | Loads the whole collection (`find(q)` then `list(...)`) and sorts/paginates in Python; sort ignores the `emp_code` tie-break; no index. | With 100k records every request reads all matching documents; page 2 order is unstable for equal dates. | DB-side `sort` + `skip` + `limit` backed by indexes; sort is `date desc, emp_code asc`. |
| 15 | `list_attendance` | No validation of `date_from`/`date_to`/`status`/`page`/`page_size`; `date_from > date_to` not rejected; page 0 yields a negative slice start; `id` leaked; legacy documents without `half_day` / `history` returned as-is. | `?page=0`, `?date_from=garbage`, `?status=XYZ` return 200. | Typed/validated query parameters, 422 on bad ranges, `attendance_out()` supplies defaults for missing fields. |
| 16 | `health` | Always returns ok, even if MongoDB is down. | Stop MongoDB: `/health` still says 200. | Pings MongoDB; any failure -> 503. |
| 17 | Module level | No startup index creation, no lifespan; connection string and database name have hard-coded fallbacks (`localhost`, `attendance_db`). | Fresh database: everything is a collection scan; wrong database silently used if env is missing. | `ensure_indexes()` in a lifespan hook (idempotent); `MONGO_URI` and `MONGO_DB` are required environment variables. |
| 18 | General | A database outage surfaces as an unhandled exception -> 500. | MongoDB down during a request. | Exception handler maps `PyMongoError` to 503. |

**Looked at and decided it was fine**
- `IST = timezone(timedelta(hours=5, minutes=30))` is correct (India has no DST), so a fixed offset is safe.
- `load_dotenv()` with its default `override=False` already lets real environment variables win over `.env`.
- `doc.pop("_id")` after `insert_one` is correct (PyMongo adds `_id` to the dict), but the same leak happened for `id` in `punch_in`, which is item 13.
- Default shifts `09:30` / `18:30` match the contract.
